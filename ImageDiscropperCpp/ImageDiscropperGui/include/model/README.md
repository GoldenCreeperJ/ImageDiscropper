# include/model — 状态源与 Core 桥接对外声明

**目录作用**：GUI **模型层**的公共头，声明会话状态单一真相源 `Document`、唯一触碰切割引擎的 `EngineBridge`，
把预处理会话态与域不变式内聚于一处的零 Qt `PreprocessSession`（由 `Document` 组合持有），
以及持有并驱动标注编辑会话 `AnnotationEditor`（组合 Core `annotation::AnnotationSet`）的标注域桥 `AnnotationBridge`。
本目录只放**类声明边界**；实现与详尽字段 / 信号说明见 [src/model/](../../src/model/README.md)。

**分块依据**：状态与 Core 调用**分离**——`Document` 只管状态（模式 / 极性 / 选区 / L2 多矩形 / L3 网格与选择集 /
导出与重排参数）并组装 `EngineConfig`；`EngineBridge` 只管调 Core API。二者分离保证「GUI 不含切割 / 几何 / 导出逻辑」
，其余 GUI 代码只经 `EngineBridge` 间接使用引擎，不直接 include 引擎实现细节。

| 文件                     | 声明                                               | 职责                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
|------------------------|--------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `document.h`           | `Document`（`QObject`）                            | 会话状态单一真相源：持有原图 `original_` / **预处理会话 `preprocess_`（`PreprocessSession`，组合轻队列 `steps_` + 独立 `resize_` + `base_` 缓存）** / 工作图 `working_` / 模式 / 极性 / 选区 / L2 多矩形 / L3 网格与选择集 / 导出与重排参数；`buildEngineConfig`（运行配置，preprocess 恒空）/ `buildSerializableConfig`（序列化配置，携带 `preprocess_.effectivePipeline()`、source 取原图尺寸）组装、`applyEngineConfig` 反向还原；`steps`/`hasPreprocess`/`geomSig`/`base*` 等预处理访问器均**转委托 `preprocess_`**（公开 API 不变），变更发 `changed()` / `imageChanged()` |
| `preprocess_session.h` | `ResizeTarget` / `PreprocessSession`（纯 C++ 零 Qt） | 预处理会话态内聚对象：声明式轻队列 `steps_` + 独立 `resize_` + `base_` 重放缓存，加 geo→color 不变式追加/块内移动限幅/载入归一化/`effectivePipeline`/`baseDirtyFor`/`geomSig`/`producesGray` 等纯策略（**静态成员供提交前算候选态、实例成员维护已提交态**）；由 `Document` 组合持有作单一真相源、`PreprocessController` 经 Document 驱动（零 Qt 故可被无头 unit_tests 直编回归）                                                                                                                                                                                   |
| `engine_bridge.h`      | `EngineBridge`（无状态、可拷贝）                          | GUI 中**唯一**触碰切割引擎的类：`loadImage` / `runPreviewGeometry`（仅尺寸跑几何、忽略 preprocess）/ `cutLines` / `buildGrid` / `exportResult` / `saveConfig` / `loadConfig`（后两者带可选 `AnnotationSet*` 参，随 SPEC §7 `annotations` 段往返）委托 `engine::*`；声明式队列物化 `applyPipeline`（委托 Core `PreprocessPipeline::applyExec`，执行层融合、与逐步 `apply` 逐像素等价）                                                                                                                                              |
| `annotation_bridge.h`  | `AnnoTool` / `AnnotationBridge`（`QObject`）       | 标注域桥：把画布手势/面板意图翻译为对编辑会话 `AnnotationEditor`（`addAnnotation`/`hitTest`/`moveAnnotation`/`change*`/`revoke`/`redo`）与 Core `buildShape`/`rasterize` 的调用（绘制/选择/移动/删除/**层序上抬/下移/置顶/置底 → `AnnotationEditor::moveAnnotation`**/撤销重做/图层可见/导出烧录 `burnIn`），另提供 `set()`（只读引用底层 `AnnotationSet` 供保存序列化）与 `replaceAnnotations()`（配置还原整体替换），发 `changed()`/`selectionChanged()`/`toolChanged()` 驱动重绘                                                                             |
| `annotation_editor.h`  | `EditType` / `AnnotationEditor`（纯 C++ 零 Qt）      | 标注编辑会话：组合 Core `AnnotationSet` + 重做栈 + 编辑模式 / 选中 / 属性模板 / 条目级撤销重做（自原 Core `AnnotationLayer` 会话半边拆出）；供 `AnnotationBridge` 委托驱动（零 Qt 故可被无头 unit_tests 直编回归）                                                                                                                                                                                                                                                                                                        |

> 命名空间统一 `idc::gui`。数据流：交互 → `Document` → `EngineBridge`（runEngine / generateCutLines / exportImage）→ `CanvasScene` 渲染。
