# include/canvas

**目录作用**：**多层画布的数据模型与像素合成**（纯逻辑、零 GUI 依赖、无文件 IO）——
`ImageLayer`（图层框节点：图案元素 + 图片元素 + 节点落位与外观，SPEC §2.2a）以 `std::vector<ImageLayer>` 集合承载（**无 `LayerStack` 包装**、**无画布级背景**、不含底图）、
`composeCanvas`（画布**先铺满全透明底**，再落底图 base、最后按 zOrder 叠叠加层：可选末位参 `base`（非空则 source-over 铺 (0,0)）；叠加层逐层物化 → 缩放 → 施 `transform.opacity` → source-over 落位，写入画布尺寸缓冲、越界自然裁剪；叠加层整体显隐由调用方以传空 `layers` 实现，Core 不持显隐态）。
承载「画布层」概念，是 GUI 图层编辑与 CLI `layers` 段共用的单一真相源。

> **术语对齐 [`SPEC.md` §2.2](../../../../SPEC.md)（权威定义）**：本模块的 `ImageLayer` 即「**图层（layer）**」——§7 `layers` 叠加层数组的一员，＝**图层框节点**（SPEC §2.2a）：有**图片元素**（`fileName` / `decodedPixels` / 内层落位任一非空）即图片层（`fileName` 引用 `<配置名>.assets/` 源图＝「**图层图片**」）；无图片元素而有**图案元素**（`backdrop`）即纯图案层（原 recipe 层合流形态，非图片）。**底图（base）**为与之同构的一条 `ImageLayer`（钉最底、恒铺满、**不入 `layers`**、不可拖拽 / 删除 / 排序），其内承载的那张图即「**底图图片**」（凭 §7 `generate` 段的内层落位声明、只存落位不存路径，位图运行时由 `--input` 供）。图片不作为程序化图案类型（`generate::PatternKind` 无 Image 枚举），仅作为 GUI「附加图片」交互入口按落点归入底图图片 / 图层图片。
>
> **引擎零改动**：多图层是「画布层」而非「引擎层」——`composeCanvas` 的产物即喂给 `runEngine` 的工作图，
> 引擎永远只收**一张展平的画布图 + 空 preprocess**。

**分块依据**：Core 只承载「无头侧也成立」的数据与像素能力；每层的**交互会话态**（选中 / 编辑 /
`base_` 缓存编排）归 GUI 的 `PreprocessSession`，Core 绝不引用 GUI 类型（CONTRIBUTING.md「分层纪律」）。
单一职责——`layer.h` 同时承载「图层数据模型」（`ImageFit` / `ImageTransform` / `ImageLayer`）与「合成入口」（`materializeLayer` / `composeCanvas` / `composeBase`）。

| 文件        | 职责                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `layer.h` | `ImageTransform`（画布锚点 `inCanvasAnchor` + 图片枢轴 `layerPivot` + 自由 `x,y` + 目标 `width,height` + `opacity`，`operator==`）、`ImageLayer`（图层框节点，SPEC §2.2a：图片元素 `fileName` + `decodedPixels` + `imageFit` + `boxWidth/boxHeight` + `imageAnchor/imagePivot/imageX/imageY` + 元素外观 `imagePreprocess/imageOpacity`｜图案元素 `backdrop` + `backdropPreprocess/backdropOpacity`｜节点 `transform` + `preprocess` + `zOrder`；`hasImageElement` 判「有无图片元素」）、`materializeLayer`（整层位图：装配序见 SPEC §2.2a 唯一口径、不含落位定位，供 GUI 按 `(layerId, 签名)` 缓存）、`composeCanvas`（`const std::vector<ImageLayer>& layers, w, h, base, materialized`：`width×height` RGBA 画布，**先铺全透明底**→落底图 base→按 zOrder 升序逐层物化→施 `transform.opacity`→source-over 落位、越界自然裁剪；可选末位参 `base`（`const core::Image&`，非空则 source-over 铺 (0,0)，缺省空图＝无底图），`materialized` 为可选预物化缓存表）、`composeBase`（把底图 ImageLayer 展平为画布尺寸像素）、`LayerPlacement`/`layerPlacement`（单层在画布坐标系的落位矩形 `{x,y,width,height}`，与 `composeCanvas` 同口径——供上层做图片图层拾取（包围盒命中、重叠取最顶）/ 拖拽定位；无可呈现位图时返 `nullopt`）。Core 不持显隐态（整体显隐由 GUI 调用方以传空 `layers` 实现） |

**约定**：`composeCanvas` 恒输出 `RGBA`；非法尺寸（宽或高 ≤ 0，或超护栏）返回空图（与 `makePattern` 同口径）。
`layers` 内存顺序不敏感，合成恒按 `zOrder` 升序（同 `zOrder` 维持原相对序，稳定排序）。画布**恒铺全透明底、无画布级背景**；叠加层整体显隐由调用方（GUI）以传空 `layers` 实现，Core 不持显隐态。`decodedPixels` **不入配置**，仅文件源且上层已解码时非空（其余为空）。
纯图案层据 `generate::makePattern` 现算、可逐字节复现（供 C++ Rust 逐像素对拍）；图片层只对拍结构（落位 / z 序 / 管线声明）。
source-over 与 `generate` 共用同一 `core::compositeOver` 真相源。
