# include/i18n

**目录作用**：Core 层的 i18n 基建头集合——三层（Core / CLI / GUI）**共用**的国际化内核，
加上 Core 自己的字符串常量层。对应 SPEC §6 NFR-11 的多语言文案基线。行为总览见顶层
[`../../../README.md`](../../../README.md)「三层共用的 i18n」。

**分块依据**：把「机制」与「文案」解耦——`core_i18n.h` 是零 Qt 的查表内核与三层共用门面，
`core_texts.h` 是被查表的字符串真相源（源语言层）。两者自成一体且被 CLI / GUI 跨层引用，
故独立于 `core/` 单列本目录；`core_nums.h`（数字常量）仍留 `include/core`。

| 头文件            | 职责                                                                                                                                                                                                                                                                                                                                                     |
|----------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `core_i18n.h`  | **i18n 内核与三层共用门面**（零 Qt，std-only）：`I18nEntry` / `I18nTable` / `makeI18nTable` + `installLanguage` / `installCoreCatalogs` / `setLanguage` / `translate` / `language` / `resolveLanguage` / `availableLanguages`；语言码常量 `kSourceLanguage`("zh-CN") / `kLangCodeEn`("en")；Core 门面宏 `IDC_KTR` / `IDC_KTRF` 与 `formatPattern`（`%1..%9` 按**编号**替换，译文可自由重组语序） |
| `core_texts.h` | **常量层 · 字符串**：按**可译性**分三组——`texts::jsonkey`（SPEC §7 键名，**不可译**）、`texts::defaults`（§7 缺字段回退值与结构体初值，**不可译**）、`texts::msg`（引擎失败报因、标注校验报因与图案显示名，**可译**，使用点经 `IDC_KTR` / `IDC_KTRF` 取译文）；消除同一键 / 同一句在写侧与读侧各写一份的漂移风险                                                                                                                                         |

> **一张进程级表同时服务三层**：GUI / CLI / Core 都链接 `image_discropper_core`，故「已登记的语言」与
> 「当前语言」在全进程只有一份，不存在各层语言不同步。各层译文表由各自装配：Core 报因的表住 Core 自己
> （[`../../src/i18n/README.md`](../../src/i18n/README.md)），GUI / CLI 的表住各自层，均由本头声明的
> `installCoreCatalogs()` / 各层 `installCatalogs()` 显式登记（不靠静态对象自注册：静态库里未被引用的
> TU 会被链接器整块丢弃，自注册会随调用点静默失效）。

> **键形态**：`<分组>::<常量名>`（如 `msg::kEngineSourceEmpty`），由门面宏经预处理器 `#` 字符串化生成，
> 回退值就是同名的中文常量——两处同源，「键拼错」与「回退值写错」都在编译期暴露为未声明标识符。跨层
> (分组, 常量名) 撞名会**静默串译文**，由 `tests/test_i18n_catalog.cpp` 断言全局唯一。

> **回退纪律**：语言未装 / 该语言缺该键 → 原样返回调用点传入的中文源值，**永不空、永不崩**。故「译文缺失」
> 永远是渐进补全，zh-CN 路径永远是零行为变化；源语言**不建表**（它的译文就是常量层本身）。

## 常量层（`core_texts.h`）

**提取判据**（与 CLI / GUI 常量层一致）：键名一律提取；§7 回退默认值按「出厂默认」提取；枚举 ↔ 串的
**成对映射表**内值串不提取（映射表即该 token 的唯一定义点）。例外：面向人的**显示名**（`generate::patternKindName`
返回的中文）进 `msg` 组，落盘用的 token 与之无关。

**类型选择**：一律 `inline constexpr char[]`（UTF-8 字节串，MSVC 三层已 `/utf-8`），不引入 `std::string`
全局对象，免静态初始化顺序与启动开销。

**引用方式**：使用点以命名空间别名简写（`namespace keys = core::texts::jsonkey;` 等）。别名一律**只落在 .cpp
或内部头**内，不进公共头——以免污染库使用者的命名空间；公共头写全限定名。

**改完怎么自检**（三层同一套路）：

1. **零孤儿**：`core_texts.h` 内每条 `kXxx` 都要能在仓库内被引用；未被引用即对应文案已删，条目连注释一起删。
2. **契约组不越界**：`jsonkey` / `defaults` 永不进语言表；只有 `msg` 进表。
3. **构建 + 单测**：Core 不依赖 Qt，`cmake --build` 后跑 `ctest`。
4. **译文表对账**：`tests/test_i18n_catalog.cpp` 直读三层常量层与译文表，断言无孤儿键 / 无重复键 /
   无跨层撞键 / 契约组不越界，并打印各组覆盖率（改名或删条目后必跑，否则错键只会静默回退而不报错）。
